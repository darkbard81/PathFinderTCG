## 1. 결과 요약

Phase 0에서 코어 전투 구성을 리더 1장과 유닛 Deck 29장, 총 30장으로 확정했다.
`GAME_DESIGN.md`의 구성물, 덱 검증 계약, Deck 존, 게임 준비, 코어 카드 풀과 테스트 매트릭스를
같은 의미로 정리했다.

카드 선언인 `card.d.ts`와 `card.schema.json`은 덱이 아니라 카드 한 장의 계약이므로 변경하지
않았다. 런타임 덱 타입, JSON Schema와 validator는 Phase 1 범위로 유지했으며 Phase 0에서
simulation이나 Phaser 구현을 앞당겨 추가하지 않았다.

## 5. 사용자 결정사항

2026-07-27에 기록된 다음 결정이 Phase 0의 승인 기준이다.

1. 전투 덱은 총 30장으로 리더 1장과 유닛 29장을 사용한다.
2. 게이트 A~F의 추천 실행 기본값은 모두 `APPROVED`다.
3. 정확한 32종 카드 이름·수치·Skill과 카드별 장면·장비·색상·자세는 게이트 B·C의 분포와
   기존 카드 계약 안에서 구현자에게 위임한다.
4. 승인 범위 안의 세부값은 추가 승인을 요구하지 않고 Phase 산출물에 전체 표와 검증 결과를
   남긴다.
5. 게이트별 재승인 조건에 해당하는 변경은 기존 값을 임의로 대체하지 않고 사용자에게 다시
   제시한다.

현재 승인 범위 안에서 Phase 1을 시작하기 위해 추가로 필요한 사용자 결정은 없다.

## 7. 고려해야 할 점

### Phase 1 덱 validator

현재 저장소에는 런타임 덱 타입, 덱 JSON Schema와 validator가 없다. Phase 1에서 이를 구현할 때
총 장수 30, 리더 1장, 유닛 29장을 한 단일 계약에서 내보내고 Schema와 TypeScript 검증이 같은
값을 사용해야 한다. Phase 0의 숫자를 여러 validator에 다시 하드코딩하지 않는다.

### 카드 풀 최소 크기

유닛 29장과 같은 정의 최대 2장 제한을 동시에 만족하려면 한 덱에 최소 15종의 유닛 정의가
필요하다. 게이트 B의 진영별 유닛 15종은 이 하한을 정확히 만족하므로, 각 진영에서 한 정의만
1장이고 나머지 14종은 2장씩 사용한다.

### 경기 길이

유닛 Deck 장수 증가는 Deck 소진까지의 최대 경기 길이에 영향을 줄 수 있다. Phase 0에서는
목표 턴 수, 시작 손 5장과 의무 드로우 규칙을 임의로 바꾸지 않았다. Phase 5 시뮬레이션과
`GAME_DESIGN.md` 21장의 대전 기록에서 실제 경기 길이와 교착 종료 시간을 측정한 뒤, 목표를
벗어날 때만 별도 사용자 결정을 요청한다.

### 승인과 구현의 구분

게이트 A~F의 `APPROVED`는 구현 기본값의 승인을 뜻하며 각 기능이 이미 구현되었다는 뜻은
아니다. 서버, 카드 풀, 이미지, Stage, AI와 프레젠테이션은 각 담당 Phase의 `Done when`을
통과해야 완료된다.
